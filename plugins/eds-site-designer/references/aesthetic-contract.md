# Aesthetic Contract

Use this reference during **DIRECT** and **LOCK**. The contract preserves the page's visual intelligence while EDS compilation changes its implementation shape.

## Direction is a decision, not a mood board

A useful direction explains why the page should look and behave this way for this content, audience, and brand. It is not a palette, a font pair, or a list of components.

Weak:

> Dark navy, teal accents, large hero, three cards.

Stronger:

> A forensic field guide where repository boundaries feel physical. Editorial headings establish the argument; monospaced identifiers reveal the evidence; one controlled transition shows the exact moment identity context breaks.

## Contract fields

| Field | Required decision |
|---|---|
| Expressive job | What the page must make the reader feel, understand, or do |
| Emotional register | Precise qualities, including productive tension or restraint |
| Visual thesis | One sentence connecting the form to the subject |
| Content metaphor | Optional organizing idea that changes composition, not decoration |
| Dominant composition | The spatial argument across the page |
| Signature moment | The one composition or interaction that should be remembered |
| Type roles | Display, body, label, technical/data, and their relationship |
| Color logic | Principal colors and the job each performs |
| Density rhythm | Where to breathe, compress, pause, and accelerate |
| Surface model | What is elevated, flat, recessed, or boundaryless and why |
| Motion principle | What motion communicates; default to restraint |
| Responsive transformation | How hierarchy and the signature moment change across widths |
| Anti-patterns | The generic or brand-breaking moves this direction rejects |
| Rejected generic alternative | A plausible safe/default composition not chosen, and the content-specific reason |

Do not fill every field ceremonially. The core lock needs the expressive job, visual thesis, dominant composition, signature moment, responsive transformation, rejected generic alternative, and observable plate/reference evidence. Include other fields only when they change a decision.

## Design-system relationship

Inventory existing tokens, fonts, components, and visual patterns. Classify each as:

- **Invariant** — deliberate project language to preserve.
- **Instrument** — available material that can serve a new composition.
- **Boilerplate** — a default, not a creative constraint.
- **Exception boundary** — may change only with explicit scope and evidence.

Do not mistake boilerplate for brand. Do not ignore deliberate system decisions merely to appear novel.

## Genericness audit

Before locking, ask:

1. Could this direction fit an unrelated company after changing copy and colors?
2. Is the signature moment actually unique, or just a large hero?
3. Does structure encode something true about the content?
4. Are all sections using the same card, radius, elevation, and alignment?
5. Did the design use the project's vocabulary in a new composition, or merely inherit its defaults?

Revise generic answers before compilation.

## Design plate requirements

The design plate should prove decisions that prose cannot:

- first-viewport hierarchy;
- dominant composition and rhythm;
- signature moment;
- representative dense and sparse states;
- meaningful interaction state when applicable;
- narrow-screen transformation when it materially changes the idea.

Use realistic content. A pristine three-card composition is not proof that one to six authored cards work.

## Lock invariants

Give every invariant an ID.

| ID | Invariant | Why | Evidence | Allowed adaptation | Failure signal |
|---|---|---|---|---|---|
| A1 | What must survive | Connection to thesis | Plate/reference | Safe changes | Observable loss |

Write invariants as outcomes, not declarations. “The CTA remains the only high-emphasis action” is stronger than “button background is green.”

## Reopening a lock

Reopen direction only when new content, brand input, accessibility evidence, or product requirements invalidate the decision. An implementation inconvenience is not automatically a direction change.
